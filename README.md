# FPK更新

**一个 GitHub 上 fpk 的下载更新器。**

你把 fpk 发在 GitHub Release 里 → 把仓库地址填进来 → 它自己认版本、后台下载、
校验 sha256 → 你点一下装上。本质就这一件事。

- 打开：`http://<NAS-IP>:18600`（端口可在应用设置里改）
- **没有登录密码，打开即用**（安全边界见下文「安全说明」）
- 独立运行：不依赖任何对话助手，也不需要装第三方商店

**两条边界（刻意的）**

1. **安装由你点，不偷偷装** —— 没装的应用也能在这里**完整安装**：自动下载、
   校验 sha256，交飞牛应用中心完成安装（可选装到哪个存储空间），装好后应用
   自动启动；但每一步都由你按下按钮才开始。
2. **下载可以自动，安装永远由你点** —— 自动替换正在运行的应用（尤其承载对话的
   Ekko Studio）风险太大，这个决定权必须在你手上。

## 它做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 任意 GitHub 仓库（或 fpk 直链）都能加进来，自动识别应用名与版本 | ❌ 不生产 fpk —— 它只搬运你已发布的包 |
| 显示真实图标、已装版本与最新版本 | ❌ 不能卸载应用（卸载请用应用中心） |
| 未安装的应用也能**完整安装**（下载→校验→应用中心装好并启动，可选存储空间） | ❌ 不会自动安装（每步都要你点） |
| 三个动作：**下载** / **安装** / **下载并更新** | ❌ 不能卸载应用 |
| 后台队列下载，关掉页面也继续，有进度与实时速度 | ❌ 不能安装任意 fpk（没有上传入口） |
| 下载前校验 sha256，安装前再复核一次；失败保留回滚包 | ❌ **不会自动安装**（检测到新版只提示 + 可选自动下载） |
| 顶栏「一键更新」：所有有新版本的应用按队列依次下载并升级（汇总条不再重复放一个「全部更新」） | ❌ 未安装的应用不进批量动作（它的包是「安装用」，单独下载更符合预期） |
| 列表排序：**添加顺序 / 字母（拼音）** 一键切换，设置记在服务端 | ❌ 不会自动按状态乱序（顺序是你定的，就不会自己跳） |

升级与你在应用中心点「更新」是**同一条通道**（服务端日志 `class=upgrade`），
区别只是按钮在这里。过程中被更新的应用会短暂重启。

## 怎么用

1. 桌面点「FPK更新」图标（fnOS 小窗打开），或浏览器直接访问 `http://<NAS-IP>:18600`
2. 卡片上看到「有新版本」→ 点右边的「下载并更新」，看进度条走完
3. 想立刻确认有没有新版：点右上角「检查更新」

### 三个动作的区别

| 按钮 | 做什么 | 什么时候用 |
|---|---|---|
| **下载** | 只把最新版安装包下到本地并校验 sha256，**不改动应用** | 想先把包存下来；或网络不稳定时先下好 |
| **安装** | 用**已经下载好**的安装包安装，不重新下载 | 包已下好，想选个合适的时间再装 |
| **下载并更新** | 下载 + 校验 + 立即升级，一步到位 | 平时就用这个 |

「安装」只在「本地已下好该版本、且与当前已装版本不同」时可用；
「下载并更新」只在确实有新版本时可用。任务进行中只禁用**该应用自己**的按钮 ——
其他应用照常可以排队（队列就是为这个做的）。

## 内建下载服务

### 自动下载（可选开关）

「设置 → 自动下载」有一个开关（默认**关**）。开了之后，每次检测到有新版本，
它会在后台把安装包**悄悄下好**；你只需要在方便的时候点一下「安装」。

⚠️ **只下载，绝不自动安装** —— 这是刻意的边界：自动替换正在运行的应用
（尤其承载对话的 Ekko Studio）风险太大，装不装、什么时候装永远由你点。

### 后台跑，关页面也继续

下载/安装都交给**后台队列**执行 —— 关掉浏览器、切走、锁屏都不影响，它在下。
重新打开页面就能看到当前进度。队列**一次跑一个**（避免几个大包互相抢带宽），
在「设置 → 后台任务」里能看到排队中的、进行中的和最近完成的。

同一个应用的同一个动作重复点只会排一次，不会堆一串。

### 进度是真实的

卡片和任务列表上显示的是**实际字节进度**：已下 / 总量、百分比、**实时速度**、**剩余时间**，
例如：

```
分段下载中… 135.0 MB / 340.7 MB · 39% · 51.9 MB/s · 剩 3 秒 · 分段加速
```

### 下载加速

两把油门，都在「设置 → 下载加速」里：

| 设置 | 说明 |
|---|---|
| **分段并发**（1–8，默认 4） | 大文件按段并发下载，明显更快。填 **1 = 不分段**（单流）。小于 4 MB 的包不分段（收益抵不过开销）。 |
| **加速镜像**（默认直连） | 到 GitHub 慢时可选 gh-proxy / ghfast / ghproxy.net / gh.ddlc.top，或填自己的前缀。 |

**安全性不因为加速而降低**：不管走直连还是镜像、单流还是分段，下完**一律过 sha256 校验**，
对不上直接删掉重来。镜像只能影响速度，改不了内容（哈希对不上会被拒）。
镜像挂了会自动回落到直连。

断点续传：下载中断后再次触发，已经下好的部分（单流的 `.part` 或分段的 `.partN`）会被复用。

### 响应式

桌面（宽屏）卡片自动多列排布，手机单列、按钮铺满一行；手机上的「设置」是全屏页，
不再是挤在小卡片里。

### 暗色模式

「设置 → 外观」三选一：

| 选项 | 行为 |
|---|---|
| **跟随系统**（默认） | 手机/电脑切到暗色，这里跟着变 |
| **浅色** | 一直浅色 |
| **深色** | 一直深色 |

选择记在本机（localStorage）**同时**写进服务端设置，所以换浏览器/换手机打开也是同一个；
首屏会用本地缓存先把主题套上，暗色下不会先闪一下白底。

### 设置分成四页

「应用」（被管理的应用）/「下载」（自动下载、加速、目录）/「外观」（主题）/
「其它」（GitHub 令牌、后台任务、运行信息）—— 手机上分页栏吸顶，切页不会丢位置。

### 像手机应用商店的那几件事

| 特点 | 说明 |
|---|---|
| **顶部汇总条** | 有更新时顶部出现「N 个应用有新版本」+「全部下载」；批量升级用顶栏「一键更新」 |
| **一键更新（顶栏）** | 一键把所有有新版本的应用排进队列，依次下载并升级（确认框里会列出是哪几个） |
| **更新说明** | 每张卡片可展开「更新说明」—— 直接显示对应 GitHub Release 的正文，装之前能看这版改了什么 |
| **失败可重试** | 任务失败的结果条上直接有「重试」，不用自己回头找按钮 |
| **有更新的排前面** | 卡片排序：正在动的 → 有新版本的 → 正常的，同级按名字。需要你看的永远在最上面 |
| **装完自动清理** | 装成功后自动删掉刚装的那个包（只在版本核验通过后才删；失败一律保留作回滚包），可在设置里关 |
| **一键清理** | 顶栏垃圾桶图标 / 设置里的「清理安装包」，先列清单再删；**只清本应用自己下载过的包** |

右上角「设置」里可以：填 GitHub 令牌、改安装包下载目录、开关自动清理、查看日志。

## 安装包清理（省点磁盘）

下载过的 fpk 不会自己消失，时间长了会占空间。这里管两件事：

### 装完自动清理（默认开）

**装成功后自动删掉刚装的那个包**。只在两道核验都过了才删：装完的版本确实等于目标版本、
且应用目录还在。任何一样不成立就**保留** —— 那时它是你的回滚包，删了就是自断后路。

装之前失败、装完起不来、版本对不上，一律不删（只留一行日志说明为什么没删）。

设置 → 下载 → 安装包清理 里可以关掉。

### 一键清理

点顶栏的垃圾桶图标，或设置里的「清理安装包」。点之前会先列出清单让你确认。范围：
本应用下载过的包 **+ 本应用自己的旧安装器**（`fpk-update-*.fpk`，可随时从 Release 重下）；
别的应用的归档包一个都不动
（有哪些包、各多大、在哪个目录），确认后才动手，之后会告诉你删了几个、释放了多少。

**只清本应用自己下载过的包**：下载完记一笔台账，装完或清完就销账。

### 为什么不把下载目录里的 fpk 全删了

因为下载目录往往同时是你的**安装包归档目录** —— 里面可能有你自己拷进去的旧版本、
或者别的脚本（定时检测之类）放进来的包，那些是回滚用的。

所以即使某个文件的名字**恰好和某个应用的当前版本一模一样**，只要不是本应用下载的，
就一个都不会动，并在界面上如实告诉你「另有 N 个不是本应用下载的，不会动」。

清理还会顺手收掉**下载残留**（下到一半失败、或下到一半换了版本留下的
`xxx.fpk.part0` 这类中间分片）—— 判定标准是「闲置超过 1 小时」，所以正在下载的分片绝不会被碰到。

逐条会拒绝的情况：目录外的文件、符号链接、非 `.fpk`、正被进行中的任务使用、
不在台账里的外来文件、目录本身。这些护栏都有真跑验证的门禁挡着
（`scripts/verify-clean-safety.py`、`scripts/verify-runtime-recovery.py`）。


## 「本应用自己」是单独一块

页面顶部有一个独立的「**本应用**」区块，管的是**更新器自己**（FPK更新）。它和下面那份
被管理列表是两回事，**不会出现在列表里**，也不会被「全部更新」带上。三个原因：

1. 更新它会**重启本应用** —— 页面上的 js/css 立刻过期，所以装完会自动刷新一次界面；
2. 把它混进「全部更新」，队列里排在它后面的应用会被这次重启**一起打断**；
3. 它没有「本机已安装」那道门（自己当然装了），而列表里每一条都要过这道门。

用法就是点那一块的「更新」：本地有校验过的包就直接装，没有就先下载再装（和列表里的
应用走的是同一套队列 / 校验 / 应用中心升级代码）。仓库可在 **设置 → 应用 → 本应用自己**
里改，留空 = 内置默认（打包本应用的那个仓库）。
旧版本里如果有过「把自己加进 apps.json」的记录，启动时会自动移出列表，你填的仓库不会丢。

## 加应用：任何仓库都行（不需要改仓库，也不需要重装本应用）

在页面右上角「**设置 → 被管理的应用**」里填一个地址点「添加」就行：

- **GitHub 仓库**：`owner/name`，或直接粘贴 `https://github.com/owner/name`
- **fpk 直链**：`https://…/xxx.fpk`（非 GitHub 也行；但直链没有 sha256 摘要，
  出于安全不会下载/安装，只用来查看版本）

添加时会先**预览**（这一步不改动任何东西），告诉你它识别出了什么：

```
识别结果：
  应用名    lemon-music
  显示名    柠檬音乐
  版本      1.2.17.7（Release tag v1.2.17.7）
  附件      lemon-music-1.2.17.7-x86.fpk（5.3 MB）
  平台      x86
  本机已装  1.2.17.7
  sha256    有
```

本机**已安装**的应用：加进来后由本工具接管升级与回滚。本机**未安装**的应用：
也可以直接加进来并完成安装 —— 卡片会显示「未安装 → 最新 vX.Y.Z」，点「下载并安装」，
在对话框里选择装到哪个存储空间（默认=系统默认卷）；如果这个应用要求填写安装参数
（端口、管理密钥、开关等，就是应用中心安装时让你填的那些），对话框里会**自动列出
同样的表单**，填写校验规则也一致（必填/格式/范围）。剩下的一条龙完成：下载 →
校验 sha256 → 由飞牛应用中心完成安装 → 自动启动。装好后本工具自动转成正常管理
（更新、回滚都在这里）。

### 为什么任何仓库都能用

版本**不是从 tag 猜的**，而是**读安装包自己的 manifest** —— 那正是 fnOS 安装时读的同一份。
所以：

| 仓库情况 | 处理 |
|---|---|
| tag 是 `v1.2.3`、`1.2.3`，或叫 `release-2026.10` 之类 | 都行，不依赖 tag 命名 |
| 附件叫 `xxx-x86.fpk` / `xxx_linux_amd64.fpk` / 随便什么 | 都行，只要求以 `.fpk` 结尾 |
| 一个 Release 有多个附件（x86 + arm） | 自动挑本机架构；也可在 `asset` 里写通配符指定 |
| manifest 在包的最前（fnpack / 本仓） | 只读开头几百 KB 就够 |
| manifest 在包的最后（第三方打包，实测柠檬音乐） | 读文件结尾；不行就整包下下来读（≤64MB 时） |
| 滚动 tag（`latest` / `nightly`）、预发布版 | 默认跳过；要的话加 `allow_prerelease: true` |

**下载完成后还会再用本地包复核一次**（读它的 manifest 确认 appname 与版本）——
检测阶段允许用启发式，但真正要装的那个包必须自己说明它是什么。

### 列表文件（也可以直接编辑）

页面上的增删会写进应用数据目录的 `apps.json`，两者等价：

```json
{
  "apps": [
    { "repo": "owner/example-fpk" },
    { "repo": "jia070310/lemon-muisc" },
    { "repo": "owner/name", "appname": "xxx", "tag": "v1.2.3",
      "asset": "*x86*.fpk", "allow_prerelease": true,
      "display": "显示名", "note": "卡片上的一句说明" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `repo` | GitHub 仓库 `owner/name`（也可写完整链接） |
| `url` | fpk 直链（替代 `repo`） |
| `appname` | 可选。不填则自动识别；填了就必须与包内一致，否则报错 |
| `display` | 可选。界面显示名，不填则用包里的 `display_name` |
| `tag` | 可选。钉住某个 Release 的 tag |
| `asset` | 可选。多附件时的通配符，如 `*x86*.fpk` |
| `allow_prerelease` | 可选。true 时也接受预发布版 / 滚动 tag |
| `note` | 可选。卡片上的一句说明 |

改完刷新网页即可，**不用重启**。

## 需要 GitHub 令牌吗？

需要，建议配上。匿名访问 GitHub 的额度是 **60 次/小时且按出口 IP 共享**
（同一个 IP 上别的程序也会用掉），实测经常不够用，检测会被限流打断。
填一个令牌可提到 **5000 次/小时**，只读权限即可。

填法：页面右上角「设置」→「GitHub 访问令牌」→ 粘贴保存（页面上只回显末四位）。
令牌只写在本机数据目录的 `github-token.txt`（权限 600），**不会随应用包分发**。

## 安全说明（本应用以 root 身份运行，且没有登录）

之所以是 root：飞牛应用中心的升级通道（unix socket
`/var/run/com.trim.app.center.sock`）只对 `OfficialAppUsers` 组开放，第三方应用用户
拿不到权限。代价是这里多了一个 root 权限的本地网页服务，因此能力被**硬限死**：

- 白名单写在数据目录的 `apps.json`，网页端无法增删应用
- 本应用自己不在被管理列表里（自身更新是页面上方独立的一块，见上一节）
- 没有任何「上传 / 安装任意 fpk」「卸载」的接口
- 只能读 `/var/apps/<白名单应用>` 的版本与图标，只能访问 GitHub 上白名单仓库
- POST 接口要求自定义请求头（挡跨站请求），且不返回 CORS 头
- 构建期有 **AST 级能力边界门禁**：静态断言后端只调用
  `appcenter-cli status/start` 和升级通道那 5 个接口，出现别的调用面直接构建失败

**没有登录密码**是刻意的（打开即用）。因此：

- 只在可信的内网使用；
- ⚠️ 若要通过公网访问，**请在反向代理那一层加认证**（例如 Lucky 的 Basic Auth /
  访问控制），不要把 18600 端口直接暴露到公网 —— 否则任何能连上的人都能触发升级。

## 数据目录

| 文件 | 说明 |
|---|---|
| `apps.json` | 被管理的应用（白名单） |
| `settings.json` | 网页「设置」里改过的项（安装包下载目录） |
| `github-token.txt` | GitHub 访问令牌（权限 600，可选） |
| `downloads/` | **默认**的安装包下载目录（可在设置里改成别处） |
| `fpk-update.log` | 运行与操作日志（页面里也能看） |
| `README-说明.txt` | 数据目录里的同一份说明 |

升级应用不会覆盖以上任何用户文件（`README-说明.txt` 会按版本重写，属应用产物）。

## 下载目录怎么选

默认是应用数据目录下的 `downloads/`。可以在「设置」里改成任意**绝对路径**，例如你
放 fpk 备份的目录。会被拒绝的几类：

| 填什么 | 为什么拒 |
|---|---|
| 相对路径 | 进程工作目录不确定，落点会漂 |
| `/` 或 `/vol2` | 太宽的根目录 |
| `/vol*/@appcenter/...` | 应用安装目录，升级时会被整体替换 |
| `/vol*/@appdata/<别的应用>` | 别人的数据目录，不许往里写 |
| `/tmp`、`/var/tmp` | 系统重启会清空，包会丢 |
